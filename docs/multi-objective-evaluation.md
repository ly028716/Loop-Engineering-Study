# 多目标评估

基准套件的加权排名适合演示一套固定偏好，但它会把成功率、成本和完成步数压缩为单一分数。多目标评估保留三个目标，使用 Pareto 前沿展示策略之间不可消除的取舍。

## 运行实验

```powershell
python experiments/multi_objective_evaluation.py
```

报告写入 `.loop/runs/multi-objective-evaluation/report.json`；其中还包含 20 条可回放的基准运行记录。

## 目标与方向

| 目标 | 方向 | 含义 |
| --- | --- | --- |
| `success_rate` | 最大化 | 五个基准场景中的成功比例。 |
| `total_cost` | 最小化 | 五次运行 Artifact 中记录成本的总和。 |
| `average_success_steps` | 最小化 | 仅在成功运行上计算的平均步骤数。 |

如果一个策略在所有目标上均不差于另一个策略，并至少在一个目标上更好，它就支配后者。没有被任何策略支配的点组成 Pareto 前沿。没有成功运行的策略将其平均成功步数视为无穷大；相同目标值的策略都保留在前沿中。

## 如何阅读结果

`pareto_front` 不是“唯一最佳策略”的名单，而是当前目标定义下仍然合理的候选集合。例如，一个策略可能以更高成本换取成功率或更少步骤。`dominated_by` 列出每个被支配策略的支配者，便于解释为何它不在前沿。

该实验复用 `benchmark_suite.py` 的确定性场景与 Artifact，不改变其既有的加权排名规则。因此两份报告回答的是不同问题：基准排名表达固定偏好；Pareto 报告显式保留偏好尚未确定时的权衡。

## 解释边界

这些结果仅适用于当前五个确定性场景、四种策略和三项目标。增加场景、策略或目标后，Pareto 前沿可能改变；在做实际决策前，应先明确成本模型与各目标的重要性。
